# Audio-to-Motion Workflow

This workflow turns a local MP3, M4A, or WAV narration into an editable, timestamped Remotion explainer without uploading audio or using a paid API. Whisper.cpp and its multilingual model stay under this project. FFmpeg performs a validated, argument-safe conversion to uncompressed 16 kHz mono PCM for transcription; Remotion uses the preserved original input for the final narration track.

## One-time setup

```bash
cd haska-ai-motion-studio
./scripts/install-whisper.sh
python3 scripts/audio_motion.py doctor
```

The reviewed installer downloads project-local CMake packages from the configured official Kali repository, whisper.cpp v1.9.5 from its official GitHub repository, and the official 466 MiB multilingual `small` model. It verifies the model's published SHA-1. It attempts a CUDA 12.4 / RTX 4060 build first and retains an optimized CPU fallback if CUDA compilation is unavailable. It does not use sudo or change system packages.

## Import and transcribe

```bash
python3 scripts/audio_motion.py import /path/to/narration.m4a \
  --name launch-explainer --title "Launch Explainer" --language ar
python3 scripts/audio_motion.py transcribe launch-explainer --language ar
```

Use `--language en` for English. `auto` is available, but an explicit language improves predictability for short recordings. Imported filenames never become shell commands; inputs must be regular MP3, M4A, or WAV files, are capped at 2 GiB, are probed for a real audio stream, and are passed to FFmpeg as separate arguments.

Each project lives at `public/audio-projects/<project-id>/`:

- `source.*`: preserved original input.
- `narration.wav`: normalized transcription input used only by Whisper.
- `transcript.json`: segment and word captions in Remotion's `Caption` shape.
- `storyboard.json`: exact scene timing, narration, text, visual type, motion description, asset requirements, and semantic rationale.
- `whisper-raw.json`: unmodified local inference output for traceability.
- `project.json`: renderer manifest generated by `activate`.

## Correct the transcript

Open `transcript.json` in a text editor. Correct `segments[].text` and `segments[].words[].text`; keep every timestamp in milliseconds and preserve chronological order. If a word must be added or split, divide the neighboring time range without overlap. Set `corrected` to `true` after listening against the narration, then run:

```bash
python3 scripts/audio_motion.py validate launch-explainer
python3 scripts/audio_motion.py activate launch-explainer
```

The validator rejects invalid bounds, reversed times, overlap, and word timings outside their segment. Word timings from Whisper are approximate and should be manually adjusted when lip/word highlighting needs tighter alignment.

## Semantic storyboard with Claude Code

Start Claude Code in the project and run:

```text
/audio-to-motion launch-explainer
```

The CLI's first storyboard is intentionally a draft. Claude must read the corrected transcript, make a content-aware scene decision for each spoken claim, explain the semantic mapping, and list any visual assets it actually needs. Audio amplitude may drive a subtle waveform or secondary pulse; it must never decide the subject of the scene.

When narration refers to a specific application or interface, provide screenshots or video references. Claude must use an abstract diagram or clearly labeled placeholder until those references exist; it must not invent exact UI steps.

## Preview and render

```bash
python3 scripts/audio_motion.py preview launch-explainer
./render-audio.sh launch-explainer youtube
./render-audio.sh launch-explainer reel
./render-audio.sh launch-explainer tiktok
```

Presets:

| Preset | Composition | Resolution |
| --- | --- | --- |
| YouTube | `AudioExplainerYouTube` | 1920×1080 |
| Instagram Reels | `AudioExplainerReel` | 1080×1920 |
| TikTok | `AudioExplainerTikTok` | 1080×1920 |

The composition duration is calculated from the probed original narration duration at 30 fps. Rendering includes that preserved source narration, exports H.264/AAC MP4, and refuses success unless ffprobe confirms a non-empty H.264 file, expected dimensions, an audio stream, and matching duration.

## Optional waveform and sound effects

`project.json` has `displayWaveform`; the default is true after activation. The waveform is a secondary, frame-synchronized layer. Licensed sound effects may be placed under `public/sfx/` only after their provenance is added to `public/sfx/licenses.json`; none are downloaded or enabled automatically.

## Per-project settings and custom scenes

`public/audio-projects/<id>/settings.json` (optional) tunes activation without touching the transcript or storyboard:

```json
{"fps": 60, "displayWaveform": false, "styleProfileId": "haska-orange-tech", "presets": ["reel"]}
```

- `fps`: 24, 25, 30, 50 or 60. All production scenes are written in seconds, so 30 and 60 fps look identical (60 fps doubles render time).
- `styleProfileId`: a built-in Style Profile (`haska-signal` is the default; `haska-cyber`, `haska-orange-tech`).
- `presets`: the presets the scenes were designed for. QA checks only these, and `render-audio.sh` refuses the others.

A storyboard scene may add optional fields to use a registered scene component instead of a built-in `visualKind`: `composition` (e.g. `reel-finale`), `engine` (`remotion` or `three`), `options` (cues in seconds from the scene start, labels), and `transitionIn` (`{type, durationMs}`). Existing storyboards without these fields are unchanged. See `src/production/render/reel/` and `REEL_TEXT` in `src/production/layout.ts` for the Reel scene set.

Transcript tip: `whisper-cli ... -sow -ml 32 -mc 0 -dtw small` produced short phrases with usable timing for Arabic dialect speech; pause-snapping (`ffmpeg silencedetect`) tightens boundaries further.

## Caption timing, sound design and fonts (Reel workflow)

- `python3 scripts/align_words.py PROJECT` re-times a corrected transcript from the recording itself: phrase boundaries snap to real pauses (or the deepest loudness valley nearby) and words are spread over speech time, snapped to loudness valleys. Whisper's own word times are unreliable for dialect speech, so this does not use them. The text is never changed.
- A project-specific recipe may regenerate a storyboard from reviewed transcript timestamps; keep such recipes in private project storage and never ship personal narration data.
- `python3 scripts/sound_design.py PROJECT` synthesizes an original soundtrack (music + sound effects) locally with numpy/scipy, with events taken from the storyboard cues. Music is ducked under the voice, the voice file is untouched, and `sound/mix-report.json` records peak, loudness and the voice-over-music margin. `npm run production -- qa PROJECT` re-checks it (including that the files still match the measured report). Nothing is downloaded and there is no third-party audio, so the output carries no attribution requirement. Judge the musical taste by ear; the report only proves the mix is safe.
- `settings.json` accepts `narrationVolume` (headroom trim for the original voice), `soundtrack` (stems placed in the project's `sound/` folder), and `showLabel`.
- Fonts: IBM Plex Sans Arabic (SIL OFL 1.1) lives in `public/fonts/ibm-plex-sans-arabic/` with its license text and a `provenance.json` (source URL, license). `FontGate` loads the files before any frame renders; QA reads glyph coverage straight from the font files. Add other fonts the same way (`src/typography/fonts.ts` + a provenance sidecar), after asking.
- Instagram Reels: the `haska-orange-tech` profile sets safe margins of 250 px top, 400 px bottom and 80 px sides; captions are at most 820 px wide so they clear the right-hand action column.
